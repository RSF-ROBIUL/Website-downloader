## কাজ তালিকা

### ১.১ Rate-limiting ও সমান্তরাল জবের সীমা 🔸 সমালোচনামূলক

**সমস্যা:** প্রতিটি socket connection-এ একটার বেশি জব নেই, কিন্তু নতুন connection-এ নতুন নতুন wget চালানো যায়। ১০০ ট্যাব = ১০০ wget প্রসেস × ১০০MB কোটা।

**করণীয়:**
- [ ] `express-rate-limit` যোগ করা (IP-প্রত نامতুল্য request-সীমা, যেমন ১৫ মিনিটে ১০টা)
- [ ] Global concurrent-job cap: সার্ভারজুড়ে সদ্য চলমান wget একসাথে সর্বোচ্চ ৩টা (env-দ্যখে: `MAX_CONCURRENT_JOBS`)
- [ ] কাউন্টার `socket/socket.js`-এর মডিউল-লেভেল ভেরিয়েবলে; সীমা পূর্ণ হলে ব্যবহারকারীকে বাংলা/ফ্রেন্ডলি মেসেজ: "সার্ভারে এখন অনেকগুলো ডাউনলোড চলছে, কিছুক্ষণ পরে চেষ্টা করুন"
- [ ] ব্যস্ত কালে (queue না থাকলে) request reject-মেসেজ UI-তে দেখানো

### ১.২ SSRF গার্ড 🔸 সমালোচনামূলক

**সমস্যা:** `wget/index.js`-এর `parseTarget()` `file://` ঠেকায়, কিন্তু `http://localhost:3000`, `http://169.254.169.254` (ক্লাউড-মেটাডেটা), internal IP সব চলে। ফলাফল জিপ public `/sites/` থেকে সার্ভ হয় — বাইরের কেউ internal network scan করতে পারে।

**করণীয়:**
- [ ] নতুন হেল্পার: `isBlockedHost(hostname)` — `127.0.0.0/8`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `100.64/10` (CGNAT), `192.0.2/24`, `198.18/15`, `::1`, `fc00::/7`, `fe80::/10` ব্লক
- [ ] DNS-রেজলভ প্রথমে (wget চালানোর **আগে**) — যাতে hostname-এর সত্যিকার IP নিরাপদ কিনা জানা যায় (DNS-rebinding প্রতিরোধ)
- [ ] localhost/`.local`/ধনটেন-আইপি নমুনা (`0.0.0.0`, `0x7f...`-স্বরূপ hex) সহ বাইপাস বন্ধ
- [ ] ব্লক হলে স্পষ্ট বাংলা error: "অনুমতি নেই — এই ঠিকানা খালিৎ ভাবে বাইরের সাইট হতে হবে"

### ১.৩ Dependency upgrade 🔸 সমালোচনামূলক

**সমস্যা:** `npm audit` ২৪ ভার্নারেবিলিটি — Express 4.19.2 ঝুঁকিপূর্ণ চেইন (body-parser DoS, cookie OOB, qs, send/serve-static), socket.io 2.x চেইন (ws 7.x high-DoS, engine.io, debug ReDoS)।

**করণীয়:**
- [ ] `express` → 4.22.3 (patch-release, breaking নয়)
- [ ] `socket.io` + `socket.io-client` → 4.8.x — client একটাই লাইন (`io.connect`), API কার্যত compatible
- [ ] `archiver` → লেটেস্ট 7.x (minor API-চেক দরকার)
- [ ] `npm audit fix` চালিয়ে প্রতিটি low/moderate মুছে ফেলা
- [ ] **সমাধানের পর** ম্যানুয়াল smoke-test: হোম-পেজ লোড, এক সাইট ডাউনলোড, এক invalid URL, এক cancel
- [ ] বাদ পড়া lockfile diff-এ টেকা রাখা

### ১.৪ Zip cleanup TTL job 🔸 সমালোচনামূলক

**সমস্যা:** `public/sites/*.zip`-এর কোনো cleanup নেই — প্রতি রিকোয়েস্ট আপ-টু-১০০MB ফেলে অসীম ডিস্ক-বৃদ্ধি।

**করণীয়:**
- [ ] `archiver/index.js`-এ সংরক্ষণ-সময় (`createdAt`) ট্র্যাক করা
- [ ] setInterval-ভিত্তিক ক্রনের-মতো ক্লিনার (প্রতি ১০ মিনিটে): `ZIP_TTL_MINUTES` (ডিফল্ট ৬০) এফেক্ট-সীমা বেশি পুরনো জিপ `fs.rm`
- [ ] `bin/www`-এ সার্ভার-স্টার্টের সময় একবার স্ক্যান: `downloads/`-এর অবশিষ্ট জব-ফোল্ডার + `public/sites/`-এর পুরনো জিপ (crash-পরবর্তী গার্বেজ)
- [ ] ক্লিনার শুধুমাত্র `public/sites/` ও `downloads/`-এর ভেতরে কাজ করবে (path-guard, `removeJobDir()`-এর মতোই)

### ১.৫ টোকেন সুরক্ষা (Math.random → crypto) 🔸 মিডিয়াম

- [ ] `views/layout.hbs`-এ `generateToken()` `randomUUID()` দিয়ে বদলে (crypto.randomUUID() ব্রাউজারে প্রস্তুত)
- [ ] localStorage-এর পুরনো টোকন যাদের আছে তারা নতুন সেশনে নতুন পাবেই (কোনো migration দরকার নেই)

## Acceptance Criteria (সম্পূর্ণ হওয়ার শর্ত)

- [ ] `npm audit` বলে 0 বা খুব-সামান্য নিম্ন-ঝুঁকি
- [ ] এক IP + অনেক tab দিয়ে wget-ফ্লাড করা সম্ভব নয় (ম্যানুয়ালি পরীক্ষা)
- [ ] `http://localhost` বা `http://169.254.169.254` দিয়ে ডাউনলোড ব্লক হয়
- [ ] পুরনো জিপ এক-ঘণ্টা পর স্বতঃই মুছে যায়
- [ ] সব আগের ফিচার (সঠিক URL ডাউনলোড, ক্যান্সেল, এন্টার-কী, error-বার্তা) আগের মতো কাজ করে
