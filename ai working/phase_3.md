# 🎨 ফেজ ৩ — UX ফিচার (Progress, Queue, History)

> **অগ্রাধিকার:** মিডিয়াম — ফেজ ১ (সুরক্ষা) শেষ হলে করা ভালো; ফেজ ২-এর সাথে পারাপার করলেও চলে।
> **সময়-খরচ (আনুমানিক):** ৩–৫ দিন।
> **সূত্র:** "high powerful downloader" বানানোর গ্যাপ-বিশ্লেষণ।

---

## উদ্দেশ্য

বর্তমানে UI কার্যত একটা "textbox + hidden লগ" — ব্যবহারকারী কী হচ্ছে তা আসলেই বুঝতে পারে না। এই ফেজে সাইটটিকে **সচেতন, অপেক্ষা-সন্তোষজনক প্রোডাক্ট-মানের UI** বানিয়ে তোলা।

---

## কাজ তালিকা

### ৩.১ আসল শতাংশ-প্রোগ্রেস বার

**সমস্যা:** এখন stderr-এর কাঁচা লগ-লাইন দেখায়; "২০০ OK" গোনা ফাইল-সংখ্যা ছাড়া কোনো প্রোগ্রেস নেই।

**করণীয়:**
- [ ] stderr parse করে wget-এর "Saving to", "Length", "xx%" প্যাটার্ন থেকে শতাংশ বের করা
- [ ] Downloaded-bytes / quota (`--quota=100m`) ভিত্তিক ব্যাকআপ-হিসাব — কোনো শতাংশ না পেলেও একটা হিন্ট-বার
- [ ] UI: ≤১০০%-এর বার + "N ফাইল ডাউনলোড হয়েছে" + বর্তমান স্টেপ (রেজলভিং → ডাউনলোডিং → কম্প্রেসিং)
- [ ] socket-ব্যক্তিমান event থেকে UI throttle (সেকেন্ডে ~৪ বারের বেশি আপডেট না — বর্তমান ফ্লাড-সমস্যা এখানেও ঠিক হবে)
- [ ] aria: `role="progressbar"`, `aria-valuenow` — প্রাচীন `<header>`-এর অব্যবহৃত `#progress` বারটিই কাজে লাগবে

### ৩.২ জব কিউ + Pause / Resume / Cancel (ব্রাউজার থেকে)

**সমস্যা:** এক connection-এ একবারে একটাই জব; pause/বাতিল UI-তে নেই (socket বন্ধ করলেই কেবল মরে)।

**করণীয়:**
- [ ] সার্ভারে পার-socket কিউ: নতুন request এলে `socket.job` ব্যস্ত থাকলে কিউতে বসে যায় ("অপেক্ষা করার অবস্থান: #২")
- [ ] UI বাটন: চলমান জবে "Cancel" (ইতোমধ্যে আছে, বাটন যোগ), অপেক্ষমাণ জবে "Remove"
- [ ] **Resume:** জব-ফাইল `removeJobDir` না-করে রাখা পর্যন্ত, Cancel-এ চেনাচেনি ID দিয়ে রাখা; পুনঃশুরুতে wget-এ `--continue` ফ্ল্যাগ যোগ
- [ ] কিউ ঠিক-ঠাক সামলানোর জন্য সরল `jobs/queue.js` মডিউল — কোনো ভারী লাইব্রেরি দরকার নেই (ফেজ ৫-এ real queue লাইব্রেরি)

### ৩.৩ ডাউনলোড-হিস্ট্রি

**সমস্যা:** পেজ-রিফ্রেশ = সব হারানো; আগে নামানো জিপ আর খুঁজে পাওয়া যায় না।

**করণীয়:**
- [ ] সার্ভার-সাইড লিস্ট: `public/sites/` স্ক্যান করে `{name, size, createdAt}` — ছোট `GET /api/history` এন্ডপয়েন্ট (ফেজ ১-এর rate-limit এর নিয়মোধিন)
- [ ] UI: নীচে "আগের ডাউনলোডসমূহ" কার্ড-লিস্ট — ফাইল-নাম, আয়তন, সময়, পুনঃ-ডাউনলোড বাটন, মুছে-ফেলা বাটন (মালিক-টেকা নিজের)
- [ ] localStorage fall-back: সার্ভার রিস্টার্ট-স্বাধীনেও নিজের সাম্প্রতিক ২০ টা ক্লায়েন্টে রাখা
- [ ] `/api/history`-তে জিপ-আছে কি না যাচাই (TTL-ক্লিনার মুছে-ফেললে কার্ড গায়েব হবে)

### ৩.৪ robots.txt ও redirect-সচেতনতা

**করণীয়:**
- [ ] ডাউনলোড-শুরুতে robots.txt পর্যবেক্ষণ — wget exit code 8 যদি robots-বারণ হয়, তবে স্বচ্ছ বাংলা মেসেজ: "সাইট-মালিক robots.txt দিয়ে অটো-ডাউনলোড বারিয়েছে"
- [ ] কোনো ফাইলও না-পড়লে আগের `explainFailure()`-বার্তা আরও জনমনঃসখ্য হবে (বর্তমানে অমদভাবেই সংযোজন)
- [ ] অপশনাল টিকড-বক্স "robots.txt এড়িয়ে চেষ্টা করুন (`--execute robots=off`)" — সক্ষম-মালিক হিসেবে এটা ব্যবহারকারীর সিদ্ধান্ত, UI-তে সাবধানতা-টেক্সট সহ

### ৩.৫ ছোট-ছোট UX খোঁচা

- [ ] URL ইনপুট validation ক্লায়েন্টেও (blank/আসবাব-ত্রুটি আগেই ধরা)
- [ ] লোডিং অবস্থায় বাটনের "spinning" icon (এখন শুধু `disabled`)
- [ ] শেষ completed-জিপের প্রাইমারি ডাউনলোড-বাটন স্পষ্ট (বর্তমান লুকানো `btn-success` বদলে স্পষ্ট কার্ড)
- [ ] মোবাইল-রেসপন্সিভ চেক (bootstrap 3 col গায়ে-গাসা মোবাইল ভাঙাতে পারে)

## Acceptance Criteria

- [ ] ডাউনলোডের সময় প্রোগ্রেস-বার এবং ফাইল-সংখ্যা প্রতিটি পাতে আসল আপডেট দিচ্ছে
- [ ] এক connection-এ ২–৩ সাইট কিউ করা যাচ্ছে, প্রতিটা ধাপ-শুরুর সময় ঠিক-অবস্থান দেখাচ্ছে
- [ ] Cancel বাটন মার লেও wget মরছে, ফাইল পরিষ্কার হচ্ছে
- [ ] পেজ-রিফ্রেশের পর আগের ডাউনলোডগুলো দেখা যাচ্ছে এবং পুনঃ-ডাউনলোড চলছে
- [ ] robots.txt-ব্লকড সাইটে স্পষ্ট মেসেজ
- [ ] মোবাইল স্ক্রিনে লে-আউট ভাবছে না
