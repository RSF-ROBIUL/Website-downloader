> **সময়-খরচ (আনুমানিক):** ২–৪ সপ্তাহ; প্রতিটি উপ-ফিচার আলাদা সিদ্ধান্ত হিসেবে তোলা যায়।
> **পূর্বশর্ত:** ফেজ ১–৩ সম্পূর্ণ; ফেজ ৪-এর ইঞ্জিন স্থিতিশীল হলে সবচেয়ে ভালো।

## উদ্দেশ্য

ব্যবহারকারী-হিসেব, স্থায়ী ক্লাউড-স্টোরেজ, developer API, রিপোর্ট-এক্সপোর্ট ও পূর্ণাঙ্গ নথি — যেসব উপাদানের সাথে এই ডাউনলোডার আর শুধু "localhost টুল" থাকে না, একটি সমাপ্ত পাবলিক পণ্য হয়ে ওঠে।

## কাজ তালিকা

### ৫.১ সাইন-ইন অ্যাকাউন্ট ও ব্যক্তিগত ইতিহাস

- [ ] অথ-প্রোভাইডার নির্বাচ: passwordless / Google-GitHub OAuth (শুরুতে Google ভালো)
- [ ] নিবন্ধিত ব্যবহারকারীদের জন্য: নিজের জব-ইতিহাস, ডেইলি ডাউনলোড-কোটা, আর্কাইভ-রিটেনশন (রেজিস্ট্রার্ড ৭ দিন vs বেনামী ১ ঘণ্টা)
- [ ] ডাটাবেস টেবিল: `users`, `jobs`, `archives` (শুরুতে SQLite, পরে PostgreSQL)
- [ ] বেনামী (guest) মোড আজের মতোই থাকবে — শুধু কোটা কম

### ৫.২ ক্লাউড স্টোরেজ (R2/S3)

- [ ] জিপ-ফাইল লোকাল `public/sites/` এ না-রেখে **Cloudflare R2** (egress ফ্রি) — প্রথম প্রস্তাব
- [ ] Signed-URL দিয়ে ডাউনলোড (সময়সীমিত লিঙ্ক)
- [ ] ভারী জিপ → ক্লাউড; লোকাল ডিস্ক শুধু metadata ও সাম্প্রতিক জিপ — ফেজ ১-এর TTL-ক্লিন-আপের সাথে সংজ্ঞা-একসাথে

### ৫.৩ Developer API (REST, api-key)

- [ ] `POST /api/v1/downloads`, `GET /api/v1/downloads/:id`, `GET /api/v1/downloads/:id/zip`
- [ ] API-কী জেনারেশন পেজ + কী-ভিত্তিক আলাদা rate-limit
- [ ] webhook অপশন: জব শেষ হলে caller-এর URL-এ POST
- [ ] OpenAPI/Swagger স্পেক + `/docs` পেজ

### ৫.৪ রিপোর্ট-এক্সপোর্ট ও বিশ্লেষণ

- [ ] ফেজ ৪-এর `report.json` থেকে PDF/Markdown রিপোর্ট — পেজ-তালিকা, ফাইল-টাইপ-ব্রেকডাউন, মোট সাইজ
- [ ] "কোন রিসোর্স ব্যর্থ/ব্লকড হয়েছে" তালিকা — সাইট-δ-diagnosis-এ সহায়ক
- [ ] রিপোর্ট ইউজার-অ্যাকাউন্টের সাথে সংরক্ষণ

### ৫.৫ ডকুমেন্টেশন ও সেলফ-হোস্টিং)
